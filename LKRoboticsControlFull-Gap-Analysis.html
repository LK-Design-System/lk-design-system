LK Robotics Control (Full)
× LK 디자인 시스템 — 커버리지 갭 분석

LK-ROBOTICS/lkrobotics-control-full(관제 풀버전 — backend + frontend)의 프론트엔드를 실제 코드 기준으로 전수 분석했습니다. 이 레포는 lk_web_viz(Tailwind, UI 킷 없음)와 달리 MUI 6 어드민 템플릿 위에 지어졌고, 화면 구성도 다릅니다 — 설비(도어·엘리베이터·계단리프트) 상태, PTZ 짐벌 텔레옵, 가스 센서 텔레메트리, 일정 캘린더가 새로 등장합니다. 결론: 제네릭 UI(폼·테이블·오버레이·내비·상태카드)는 이미 전부 커버되고, 새로 발견된 갭은 7개 — 이 중 2개(설비 상태 카드, 비디오 스트림 타일)가 우선순위 P1입니다.

◆ 제네릭 UI = 커버 · 신규 갭 7개(P1 2 · P2 3 · P3 2) — P1 2개 구현 완료(2026-07-04) · 범위 밖 3건

03 신규 갭 — 이 레포에서 처음 발견

lk_web_viz 감사 때는 없던 화면들. 우선순위 P1(반복·상시 노출) → P3

구현 완료 설비 상태 카드(도어 · 엘리베이터 · 계단리프트) robotics/EquipmentStatusCard · 2026-07-04

아이콘+타이틀 헤더, 큰 원형 상태 링(OPEN/CLOSE/LOCK·층수·위치 라벨), 점멸 방향 화살표(이동 중), 하단 상태 칩 로우 — 세 컴포넌트가 토씨 하나 안 틀리고 같은 골격을 각자 구현했습니다. 대시보드에 그리드로 상시 노출되는 실사용 패턴(주석 처리된 죽은 코드 아님). AutoDoorStatus · ElevatorStatus · StairLiftStatus

구현됨 — robotics/EquipmentStatusCard: 아이콘 · 타이틀 · 원형 상태 링(라벨+톤) · 옵션 방향 화살표(점멸) · 상태 칩 배열 — 제안된 prop 그대로 구현. 세 화면을 prop 조합 하나로 흡수.

구현 완료 라이브 비디오 스트림 타일 viz/VideoStreamTile · 2026-07-04

RTSP/WebRTC <iframe> + 코너 라벨 배지 조합이 로딩/에러 상태 없이 반복됩니다. RGB/IR/EO 스트림을 나란히 배치하는 레이아웃도 3곳에서 동일하게 손으로 재구현. LiveMonitoring · ManualControl(TRON/PATROL 레이아웃)

구현됨 — viz/VideoStreamTile: iframe/video 래퍼 + 코너 라벨 칩 + 로딩·연결끊김 상태 — 제안대로 구현. 렌더 소스(iframe src)는 그대로 앱이 주입 — viz 그룹의 기존 경계 계약과 동일.

P2 PTZ/짐벌 제어판

드래그 조이스틱 자체는 Joystick과 일치하지만, 이를 감싸는 줌 홀드 버튼 · 오토포커스 토글 · 모드 세그먼트(follow/lock/reset/off) · 홈 버튼까지 묶는 전용 컴포지트가 없습니다. LKWebViz 감사에서 P3로 남았던 "짐벌 팬/틸트 컨트롤" 갭과 같은 계열입니다. manual-control(TRON PTZ 패널)

현재로도 조합 가능 — Joystick + SegmentedControl + Button + Switch. 반복 빈도가 높아지면 robotics/GimbalControl 프리셋으로 굳히는 걸 권장.

P2 이산형 방향 키패드(WASD/D-패드)

Joystick은 아날로그 드래그 전용(연속 −1..1). 실제 앱은 이와 별개로 이산 키 그리드를 씁니다 — 눌림 상태가 실제 키보드 이벤트와 실시간 동기화되는 시각적 키캡(W/A/S/D + Space/Enter), 별도 화면에서는 원형 IconButton D-패드. manual-control(Key 컴포넌트) · Controls(구버전, 현재 미사용)

제안 — Joystick에 mode="pad" 변형 추가(키캡 그리드 + active 하이라이트), 별도 컴포넌트 신설보다 프롭 확장이 적합.

P2 일정/이벤트 캘린더

DS의 Calendar는 날짜 선택용 월 그리드(데이트피커)입니다. 앱은 @fullcalendar/react로 월/주/일/목록 뷰 전환 + 이벤트 블록 렌더 + prev/next/today 툴바를 갖춘 어젠다형 캘린더가 필요합니다 — 근본적으로 다른 컴포넌트입니다. schedule/CalendarView

viz/editor와 같은 경계 계약 권장 — 무거운 캘린더 렌더(FullCalendar)는 앱에 남기고, DS는 툴바 버튼 스타일 · 뷰 전환 세그먼트 · 이벤트 칩 톤 같은 크롬 토큰만 제공.

P3 차트 임계값 주석선

TelemetryGauge엔 thresholds(색상 구간)가 있지만 BarChart엔 없습니다. 가스 센서처럼 "위험선"을 막대 위에 그어야 하는 케이스에 대응 안 됨(현재는 ApexCharts annotations로 앱이 직접 구현). GasSensorChart

제안 — BarChart에 thresholdLine?: number 프롭 추가.

P3 아이코노그래피 · FloorSelector 배지

배터리 세부 단계 아이콘(7단계 충전율)과 도어·엘리베이터·계단 전용 글리프가 78종 세트에 없습니다(배터리는 TelemetryGauge가 이미 더 나은 대체재). FloorSelector엔 층별 보조 상태(엘리베이터 도착/이동 표시)를 얹을 슬롯도 없습니다 — 현재는 층 이름만 표시. RobotList 배터리 아이콘 · LiveMonitoring 층 레일의 점멸 화살표

제안 — 아이콘 확장은 선택 사항(배터리는 게이지로 대체 권장); FloorSelector엔 floors 항목에 옵션 badge 노드 슬롯 추가.

04 범위 밖

  • ControlSocketTest — 순수 HTML <input>/<button>로 짠 소켓 프로토콜 테스트 도구. MUI조차 쓰지 않는 dev/QA 전용 화면 → 감사 범위 제외.
  • Berry 템플릿 보일러플레이트 — dashboard/Default(샘플 차트 4종) · Customization(폰트/반경 테마 패널) · sample-page — 실제 프로덕트 화면(RobotDashboard)과 별개인 어드민 템플릿 기본 스캐폴드로 판단 → 제외.
  • MUI 테마 자체 — src/themes/ 커스터마이징은 UI 프레임워크 레벨 선택이라 컴포넌트 커버리지 범위 밖(05 권고에서 별도로 다룸).

05 권고

  • 즉시 채택 가능 — 폼 · 테이블 · 오버레이 · 내비 · 상태카드는 이미 대응 컴포넌트가 있으니, 신규 화면부터 LK DS로 직접 작성.
  • 스택 유의 — 이 레포는 MUI 6 전면 도입 상태라 (UI 킷이 없던 lk_web_viz와 달리) 전환 비용 성격이 다릅니다. 신규 화면은 DS로, 기존 MUI 화면은 화면 단위로 점진 교체를 권장하고 — 사이트 전역에 LK 토큰을 입히려면 MUI ThemeProvider 팔레트/타이포를 LK 토큰에 매핑하는 별도 작업이 필요합니다(둘 중 무엇을 할지는 별도 결정 사항).
  • 신규 컴포넌트 2개(P1) — 구현 완료 — robotics/EquipmentStatusCard, viz/VideoStreamTile (2026-07-04). 세 화면이 이미 손으로 중복 구현한 패턴이라 ROI가 가장 높았습니다.
  • 기존 컴포넌트 보강(P2) — Joystick에 이산 키그리드 모드, FloorSelector에 배지 슬롯, BarChart에 임계값 라인.
  • 캘린더는 경계 계약으로 — FullCalendar는 앱에 남기고 DS는 툴바/이벤트 칩 크롬 토큰만(viz/editor와 동일한 원칙).
