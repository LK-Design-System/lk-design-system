커버 이미지 · 제목 · 아이콘 메타 행(기간·분류) · 상태 배지(진행중·마감)로 구성되는 **리스팅/이벤트

## 왜 별개 컴포넌트인가 (NewsCard 확장이 아니다)

외부 참조(채용·이벤트 사이트의 카드 그리드)는 겉모습이 `NewsCard`와 닮았지만 **의미가 다르다**.

| 슬롯 | NewsCard (기사·보도) | 리스팅 카드 (모집·이벤트) |
| --- | --- | --- |
| 날짜 | 발행일(`date`/`dateTime`) | 모집·행사 **기간**(시작~종료) |
| 보조 | 출처·바이라인(`source`) | **분류 태그**(직군·유형) |
| 상태 | 없음 | **모집 상태 배지**(진행중·신청 마감) |
| 액션 | "자세히" 읽기 유도 | 등록·신청 |

`NewsCard`의 계약은 "article/press card"이며 `category`·`excerpt`·`source`·`date`는 **읽을거리의
발행 정보** 문법이다. 여기에 모집 상태·기간·분류를 얹으면 "출처"와 "모집 상태"가 같은 슬롯을 두고
경쟁하고, 소비자는 이 카드가 기사인지 이벤트인지 알 수 없게 된다 — 시각적 유사성으로 이질적 의미를
한 컴포넌트에 욱여넣는 것은 이 저장소가 가장 경계하는 실수다. 따라서 **NewsCard 확장이 아니라 별개
컴포넌트**가 의미상 맞다.

## 왜 지금 보류인가 (제품 근거 없음)

`COMPONENT_WORKFLOW.md`는 "제품의 현재 anatomy를 LDS 공용 설계로 승격하지 않으며, LDS
sibling·WDS·권위 있는 외부 category reference에서 독립적으로 도출한다"고 요구한다. 그런데 이
패턴을 요구한 근거는 현재 **외부 마케팅 사이트뿐**이고, 고정 제품 소스에는 근거가 없다.

- 고정 제품(**LK Web Viz**, **LK Control Full Daedeok**, **LK Context Hub**)의 커버리지 원장
  (`docs/references/product-frontends/COVERAGE_AUDIT.json`)에 커버 이미지 기반 카드 그리드나
  모집/이벤트 리스팅 표면의 판정이 없다. 관제 제품의 목록 표면은 `DataGrid`/`Table`(행 기반),
  `DescriptionList`(키-값), `ReorderList`(정렬 목록) 중심이다.
- 세 제품은 로컬에 체크아웃돼 있지 않아 소스를 직접 재확인하지 못했다(현재 `unverified`).

지금 만들면 관제 제품이 아니라 **외부 채용 사이트의 카드 해부를 DS로 승격**하는 것이 되어 위 규칙과
정면으로 어긋난다. 그래서 보류한다.

## 착수 트리거

다음 중 하나가 확인되면 이 제안을 다시 연다.

- 고정 제품(또는 새 소비 제품) 소스에 "제목 + 기간 + 상태 배지"를 가진 **리스팅/카드 그리드**가
  실제로 있음이 확인될 때. 관제 도메인에서도 로봇 **작업 목록**(작업명·기간·진행 상태), 배포 **잡
  목록**, **이벤트·알람 카드**가 이 해부를 요구할 수 있으므로, 관제 도구라고 해서 없다고 단정하지
  않는다 — 소스로 확인한다.
- 확인되면 그 **실제 해부**(어떤 상태 어휘, 어떤 메타 필드, 카드 vs 행 판정)를 근거로 API를
  도출하고, 외부 category reference(마켓/이벤트 리스팅 카드, seed-design `Article`/card, Material
  supporting-text+status card)와 대조한다.

## 소유 경계 (만들 경우)

- **DS가 소유**: 커버(장식/정보성 alt 판단은 NewsCard 선례), 제목 heading 레벨, 아이콘 메타 행의
  조판, 상태 배지의 시각·의미(재사용: `StatusBadge` 또는 `ContentBadge`), 카드=링크 계약과 그리드
  정렬의 시각·접근성.
- **제품이 소유**: 데이터, 모집 상태 계산, 기간 포맷, 필터·정렬·페이지네이션, route.
- **재사용**: 상태 배지는 신설하지 않고 `StatusBadge`(점+라벨) 또는 `ContentBadge`(라벨 칩)를,
  분류 태그는 `Tag`를, 그리드는 `Grid`/`DashboardGrid`를 조합한다.

## 결정 요청

이 문서는 **만들지 말지의 게이트**다. 지금은 보류가 기본값이며, 그동안 제품은 원자(`Card`/
`Thumbnail`/`StatusBadge`/`Tag`/`Grid`)로 리스팅 카드를 조합한다. 착수 트리거가 실현되면 실제 제품
해부를 근거로 다시 연다.
