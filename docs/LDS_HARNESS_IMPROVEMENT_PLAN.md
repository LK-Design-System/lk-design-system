이 문서는 LDS를 **DS 본체 · 계약 · 하네스**로 나눠 본 감사(2026-09-24)의 결론과, 하네스를
다음 수준으로 올리기 위한 단계·종료 조건·지표를 소유한다. 감사 수치는 그 날짜의 관찰이며
현재 값의 정본이 아니다.

## 1. 세 층 모델

| 층 | 무엇 | 예 |
| --- | --- | --- |
| DS 본체 | 제품 화면이 실제로 그리는 것 | 토큰, 컴포넌트, 아이콘·심볼, 스타일, 타입 램프 |
| 계약 | 본체를 기계가 읽고 검증할 수 있게 적은 것 | `.d.ts`, play 단언, `.prompt.md`, 생성된 레지스트리·카탈로그, 시각 기준선 |
| 저작 하네스 | LDS 자체를 고치는 과정을 통제 | AGENTS.md, 워크플로 문서, `check:*`·생성기, 품질 기준선, CI, 결정 기록 |
| 소비 하네스 | 패키지와 함께 실려 나가 제품 repo의 사용을 이끄는 것 | `lds-ui`·`lds-deck` 스킬, 적용 계약, conformance, `lds-slides-check` |

원칙: **결정은 DS 본체와 계약 층에만 둔다. 하네스는 결정을 가리키고 집행할 뿐 복제하지
않는다.** 하네스가 버전·개수·토큰 값·목록을 옮겨 적는 순간 그 사본이 어긋날 수 있고, 소비
하네스라면 그 어긋남이 제품 repo의 에이전트에게 정본처럼 전달된다.

### 감사에서 드러난 사각지대

- **조합 단위 일관성** — slides 게이트가 모두 통과한 상태에서 덱 안 제목 높이가 슬라이드마다
  38 설계 px 달랐다. 게이트는 한 장을 보고 한 덱을 보지 않았다.
- **반쪽 검사** — 정해진 줄만 대조(core inventory), 링크·경로만 확인(robotics `check:docs`의
  작성 문서 부분), 재생성하고 diff하지 않음(3d evidence). 검사가 있다는 사실이 검사되지 않는
  줄을 가렸다.
- **선언만 있는 MANDATORY** — "외부 레퍼런스 2개", "형제 컴포넌트와 나란히 렌더해 비교" 같은
  규칙을 확인하는 수단이 없다.

## 3. 원칙

1. **실패가 사람에게 닿지 않으면 게이트가 없는 것과 같다.** 게이트 추가보다 실패의 전달이 먼저다.
2. **선언은 검사로 바꾸거나, 판단이 필요하면 판단하는 역할에게 넘긴다.** 확인 수단 없는
   MANDATORY를 두지 않는다.
3. **하네스는 가리키고 복제하지 않는다.** 산문 속 사실은 생성하거나 검사로 묶는다. 역사적
   사실("rc.69.28에서 생겼다")은 복제가 아니며 남겨도 된다. 현재 상태 주장은 정본을 가리킨다.

## 4. 단계

각 단계는 종료 조건을 만족해야 닫는다. 순서는 효과 대비 비용이다.

### H0 — 감사 발견 정리

- 감사 커밋 4개(core·robotics·slides·motion)를 원격에 반영하고 CI·배포 완료까지 확인한다.
- 3d 발견 5건을 3d의 진행 중 작업과 합쳐 반영하고, 3d CI를 초록으로 되돌린다.
- **다음 짝 릴리스에 포함할 것**: `lds-ui` 스킬(`docs/agent-skills/lds-ui/SKILL.md` 모션 절)의
  "fast 120ms / base 200ms / slow 320ms"를 토큰 이름(`--dur-fast` / `--dur-base` / `--dur-slow`)과
  "값은 expression profile이 정한다"로 바꾼다. 2026-09-24에 반영했다가 되돌렸다 — 스킬은 core
  문서 manifest에 투영되고, 그 manifest의 지문은 vendored Robotics 패키지가 릴리스 때 고정하므로,
  core 버전이 그대로인 채 문서를 바꾸면 `check:type-surface`가 짝 Robotics 릴리스 전까지
  실패한다. 스킬 문구 변경은 Core·Robotics 짝 릴리스와 함께 나간다.
- **종료 조건**: 다섯 repo의 `main` CI가 모두 초록이고 감사 발견 중 보류(pastel) 외 미처리 0.

### H1 — 강제 시점 앞당기기

- **CI 상태판**: LDS repo 전체의 최근 `main` CI 결과를 모아 보여주는 워크스페이스 스크립트와
  정기 실행. 실패가 있으면 알린다.
- **push 전 빠른 게이트**: 각 repo에 pre-push 훅. 2분 안에 끝나는 정적 검사(타입, 스타일
  소유권, 카탈로그·문서 drift)만 돌리고, 무거운 검사(Storybook 빌드, 시각 회귀)는 CI에 둔다.
- **에이전트 훅**: 에이전트 설정에서 `git push` 전에 같은 빠른 게이트를 강제한다.
- **종료 조건**: 의도적으로 깨뜨린 커밋이 push 단계에서 멈추고, 의도적으로 실패시킨 CI가 하루
  안에 알림으로 도착한다(두 번 모두 재현 기록을 남긴다).

### H2 — 선언을 검사로

- 각 repo AGENTS.md의 MANDATORY 규칙을 목록화해 셋 중 하나에 배정한다:
  ① 스크립트 검사(예: 새 컴포넌트 `.prompt.md`의 외부 레퍼런스 절에 링크 2개 이상),
  ② 증거 파일 검사(예: 제품 워크플로 판정이 `COVERAGE_AUDIT.json`에 존재),
  ③ 사람 판단 — H3의 리뷰어 역할이 맡는다.
- "Status: Current" 문서는 검사 대상이 되거나 Historical로 내린다.
- **종료 조건**: 배정되지 않은 MANDATORY 규칙 0. ①·②는 `npm run check` 경로에 연결됨.

### H3 — 역할 분리와 동시 작업

- **읽기 전용 리뷰어 에이전트**: 쓰기 권한 없이 시각 차이 목록, 형제 컴포넌트 비교, H2 ③
  규칙 확인을 맡는다. 구현 에이전트와 분리해 "독립 리뷰"를 실제로 만든다.
- **동시 작업 규칙**: repo `main` 체크아웃에서는 한 세션만 작업하고 다른 세션은 worktree를
  쓴다. 규칙은 각 repo AGENTS.md의 동시 작업 절에 둔다.
- **종료 조건**: 새 컴포넌트·실질 재설계 1건이 리뷰어 산출물(차이 목록·반박 기록)을 거쳐
  병합됨. 같은 repo에서 두 세션이 main을 동시에 수정하는 경우 0.

### H4 — 사각지대 검사

- **조합 단위**: slides는 "덱 안 콘텐츠 제목 높이가 하나"를 게이트로 둔다. core는 패턴 스토리
  단위로 같은 방식(여러 컴포넌트가 한 화면으로 읽히는지)을 적용할 후보를 고른다.
- **반쪽 검사 보완**: 재생성 단계에 diff를 붙이고(3d evidence), 정해진 줄만 보는 검사는 범위를
  넓히거나 검사하지 않는 범위를 문서에 명시한다.
- **산문 사실**: slides의 방식(값 모듈 하나를 게이트와 문서 검사가 함께 읽음)을 core·robotics의
  소비 하네스 문서로 넓힌다.
- **종료 조건**: 감사에서 찾은 세 사각지대 유형 각각에 게이트 하나 이상.

### H5 — 하네스 자체 점검

- slides `qa/` 방식을 `lds-ui` 스킬로 확장: 스킬만 읽은 에이전트의 산출을 conformance로 채점해
  가이드의 효과를 측정한다.
- 세 층 감사를 분기마다 반복해 결정 복제를 추적한다.
- **종료 조건**: 두 번 연속 분기 감사에서 새 결정 복제 0.

## 6. 하지 않을 것

- **게이트 수만 늘리기.** core 전체 검사는 이미 수십 분이다. 느린 하네스는 우회된다 — 빠른
  게이트는 push 단계로, 무거운 검사는 CI로 나눈다.
- **하네스를 하나로 합치기.** 용도별 분리(`lds-ui`, `lds-deck`, robotics·3d 참조)를 유지한다.
- **모든 판단을 스크립트화하기.** 디자인 적합성처럼 판단이 필요한 것은 리뷰어와 루브릭의 몫이다.
- **SSOT를 규칙 문서 한 벌로 모으기.** LDS의 정본은 코드·토큰이고 문서는 생성물이다. 규칙
  문서로 정본을 옮기면 약해진다.
