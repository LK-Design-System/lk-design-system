데이터로 주장을 만드는 절차를 정의한다. 적용 범위는 LDS 계열에서 **데이터로 주장을 만드는
모든 표면** — 발표 자료, 문서, 대시보드 요약, Storybook 가이드 — 이며 특정 저장소에 매이지
않는다. 그래서 이 문서는 Core가 소유하고, 코드로 강제할 수 있는 단계의 집행 장치는 LDS
Editorial이 소유한다. 문서와 코드가 충돌하면 코드가 이기고 이 문서를 갱신한다.

근거 소스와 채택 결정, FT Visual Vocabulary 카테고리별 소유 판정은 Editorial 저장소의
`docs/references/`가 소유한다.

---

## 절차: 질문 → 주장 → 형태 → 강조 → 검증

모든 데이터 그래픽은 이 다섯 단계를 순서대로 통과한다. 앞 단계를 건너뛴 그래픽은
뒤 단계에서 고칠 수 없다.

### 1. 질문 — 독자가 답을 얻어야 할 질문을 한 문장으로 쓴다

- 질문이 쓰이지 않으면 그래픽은 시작하지 않는다. 질문 없는 그래픽은 데이터 장식이다.
- 질문은 독자의 언어로 쓴다: "처리량이 얼마나 늘었나?", "어느 라인이 가장 뒤처졌나?"
- 질문이 두 개면 그래픽도 두 개다. 하나의 도판에 질문을 겹치지 않는다.

### 2. 주장 — 데이터가 지지하는 답을 한 문장으로 쓴다

- 주장은 제목이 된다. "주간 처리량 추이"가 아니라 "라우팅 교체 후 주간 처리량 18% 증가".
  (Urban Institute의 active title 규칙)
- **그래픽 안의 카피는 명사형으로 닫는다**: 제목만이 아니라 주장·주석·각주까지 —
  "~올라섰다"가 아니라 "1위 달성", "~배치됐다"가 아니라 "신규 물류동 배치".
  서술형 종결어미("~다")는 Docs 산문과 접근성 설명문의 것이고, 그래픽 표면의 카피는
  최대한 명사로 압축한다. 워크드 예제의 play 단언이 이를 검증한다.
- 주장을 쓸 수 없으면 — 데이터가 아직 아무 말도 하지 않으면 — 그래픽을 만들지
  않는다. 중립적 참조가 목적이면 표나 기본 차트가 정직하다.
- 주장이 데이터에 의해 실제로 지지되는가는 **사람의 판단**이다. 어떤 컴포넌트도
  거짓 주장을 막지 못한다.

### 3. 형태 — 질문 유형으로 그래픽을 고른다. 취향으로 고르지 않는다

- 질문을 FT Visual Vocabulary 카테고리에 대응시키고, Editorial 저장소
  `docs/references/VISUAL_VOCABULARY_MAP.md`의 판정(소유 / 조립 / 밖)을 따른다.
- "얼마나 큰가" → `KeyFigure`·`PictogramRow`. "무엇이 변했나" → Core 차트 조립 +
  주석. "몇 등인가"·"기준 대비 얼마나" → 로드맵 컴포넌트 전까지 Core 차트 조립.
- 판정이 **밖**(Spatial)이면 여기서 만들지 않는다 — Robotics/3D로 간다.
- 형태 선택은 메시지가 정한다 (EU 가이드의 message-first). 데이터 타입이 같아도
  주장이 다르면 형태가 달라진다.

### 4. 강조 — 주장을 가리키는 요소 하나만 세운다

- **강조는 한 번에 하나.** 강조 토큰은 `--editorial-emphasis` 하나뿐이고,
  `AnnotatedFigure`는 복수 강조 요청에서 첫 번째만 승인한다. (코드 강제)
- 도판 사이의 경쟁은 매체가 중재한다: 슬라이드에서는 `StatSlide`가 첫 요청만
  승인하고, 강조를 쓴 슬라이드는 악센트 eyebrow를 내린다. (코드 강제)
- 강조되지 않는 모든 것은 침묵한다: `--editorial-muted`, 무채색, 낮은 밀도.
  Robotics의 평시 밀도 원칙과 같다 — 모두가 소리치면 아무도 안 들린다.
- 주석은 데이터 옆에 선다. 데이터 위에 얹지 않는다. (코드 강제)

### 5. 검증 — 배포 전 체크리스트

- [ ] 정확한 값이 텍스트로 병기되는가 (그래픽·색만으로 수량을 말하지 않는가)
- [ ] 흑백으로 바꿔도 주장이 읽히는가
- [ ] 길이·면적으로 크기를 말하는 그래픽(막대·면적·픽토그램)의 축이 0에서 시작하는가
- [ ] 위치로 추세를 말하는 선·점 그래픽은 **0 강제 대상이 아니다** — 축을 데이터 범위에
      맞추되 눈금을 명시했는가, 그리고 배율 주장("~% 증가")이 핵심이면 0 시작이나
      변화율 축으로 배율을 정직하게 보여주는가
- [ ] 축을 데이터에 맞출 때 **선이 프레임에 닿지 않는가** — 데이터 범위 위아래로
      여유를 두고, 눈금은 라운드 값으로 잡는다. 꽉 붙은 축은 정직하지만 읽기 나쁘다
- [ ] 카테고리가 7개 이하인가 (파이라면 5개 미만인가)
- [ ] 이중 축이 없는가
- [ ] 픽토그램 스케일 범례가 선언되는가 (단위당 값 ≠ 1일 때, 코드 강제)
- [ ] 출처·기준 시점이 표기되는가
- [ ] 접근성 이름이 정확한 값을 전달하는가 (코드 강제)
- [ ] 매체에 얹었을 때 읽는 거리가 맞는가 — 슬라이드면 투사 스케일로 해석되는가
      (코드 강제: Slides의 `ProjectionSeam` 단언)

## 집행 구분

방법론은 세 등급으로 집행된다. 새 규칙을 추가할 때는 가장 강한 등급으로 내려앉힌다.
play 등급은 Editorial·Slides의 `npm run check:storybook`이 모든 스토리의 play 함수를
헤드리스 Chromium에서 실행해 보증한다 (`story-play-known-failures.json` 래칫).

| 규칙 | 집행 등급 |
|---|---|
| 강조는 한 번에 하나 (도판 내부) | **코드 강제** — `AnnotatedFigure` 승인 로직, 강조 토큰 단수 |
| 강조는 한 번에 하나 (매체 범위) | **코드 강제** — `StatSlide` 예산 집행, eyebrow 강등 |
| 값 텍스트 병기, 접근성 이름 | **코드 강제** — `KeyFigure`·`PictogramRow` 구조 |
| 픽토그램 스케일 범례 | **코드 강제** — `PictogramRow` |
| 주석은 데이터 옆에 | **코드 강제** — `AnnotatedFigure` 레이아웃 |
| 매체별 읽는 거리 | **코드 강제** — `--editorial-*` 램프를 매체가 재지정 |
| 영 기준선, 카테고리 수, 이중 축 금지 | **play 단언** — 조립 스토리에서 검증 (로드맵) |
| 제목·주장 카피의 명사형 종결 | **play 단언** — 워크드 예제에서 "~다" 종결 시 실패 |
| 주장형 제목, 질문-주장 일치 | **사람 판단** — 리뷰에서 이 문서를 인용한다 |
| 주장이 데이터에 지지되는가 | **사람 판단** — 어떤 코드도 대신 못 한다 |

## 안티패턴

지향하지 않는 것을 명시한다. (LDS DESIGN.md의 avoid 목록과 같은 지위)

- **주장 없는 차트** — 제목이 데이터 이름만 반복하는 그래픽. 절차 1·2를 건너뛴 증거.
- **강조 남발** — 세 가지 색으로 세 가지를 강조하면 주장이 세 개라는 뜻이고,
  그건 그래픽이 세 개여야 한다는 뜻이다.
- **동등하게 요란한 KPI 타일의 벽** — Core DESIGN.md에서 상속.
- **잘린 축으로 만든 드라마** — 막대의 축을 자르거나, 배율 주장을 하면서 축을 조이는 것.
  변화가 작으면 작다고 말한다. 추세를 말하는 선 차트의 조인 축은 드라마가 아니라
  해상도다 — 0 강제는 크기 부호화(길이·면적)의 규칙이지 위치 부호화의 규칙이 아니다.
- **색만으로 구분되는 범례** — 직접 라벨링이 우선이고, 색은 보조 채널이다.
- **픽토그램만으로 말하는 수량** — ISOTYPE은 반복 강조 장치이지 측정 표기가 아니다.
- **장식 3D·그라데이션·네온** — 브랜드 인격(정밀·차분·산업적)에서 상속.
- **매체를 가정한 서사 컴포넌트** — 컴포넌트가 업스트림 타입 램프를 직접 참조하면
  한 매체의 읽는 거리를 박아넣게 된다. 순위는 컴포넌트가, 거리는 매체가 소유한다.

## 워크드 예제 (로드맵)

방법론은 규칙 목록보다 예제로 가르친다. 각 카테고리마다 같은 데이터로 절차를
지킨 판과 어긴 판을 나란히 보여주는 before/after 스토리를 Editorial Storybook에
추가하고, play 단언으로 "지킨 판"이 실제로 규칙을 지키는지 검증한다.
