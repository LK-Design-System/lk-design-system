# WDS ↔ LDS Component Axis Coverage

Generated by comparing each WDS component's variant axes (decoded from the local
`.fig`, `FIGMA_LOCAL_CONTENT_AUDIT.json` → `componentSections[].variantAxes`)
against the matching LDS component `.d.ts` prop surface. Enum axes (Variant /
Size / Color / Status / State / Render / Type / Align / Position / Length /
Resize) are value-diffed; boolean state axes and platform axes are informational.

Bleed note: the `.fig` section extraction sometimes merges variant symbols from
adjacent components, so a few axes appear on the wrong component (flagged below).

## Fully covered (fig axis values all present in the LDS prop surface)

Button, Alert, Avatar, Category, Chip, Content Badge, Control (checkbox/radio
State), Divider, Icon Button, Loading, Skeleton, Text Button, Tooltip,
Segmented Control, Page Indicator, Menu.

| Component | Missing | Notes |
|---|---|---|

| **Tabs** | **Alternative** variant | No `variant` prop (size only). |

## Modeled differently (decide mapping, not literal gaps)

| Component | Situation |
|---|---|
| **ActionArea** | WDS "Action Area" is a 12-variant action element (Button/Cancel/Checkbox/Chip/Summary…); LDS ActionArea is a sticky action-bar container (summary/compact/sticky). Different abstraction. |
| **ChoiceCard** | WDS `Type: radio/checkbox` is modeled by LDS `multiple` boolean — not a gap. |
| **Dot / PageIndicator** | WDS "Dot" display variants (Extended/Minimize/White) vs LDS `counter/dot/dots`. Ambiguous mapping. |

## Filtered as fig bleed (not real)

- Textinput `State` (Checked/Indeterminate/Unchecked) + `Type` (Checkbox/Radio) + `Render` (Chip) — bled from Control / Select.
- Tab `Compact/Extended/Minimize/White` variant values — bled from Dot.
- Menu `Align: Bottom/Center` — false positive (covered).
