채택 · 토큰 매핑 가이드

갭 분석의 1·2순위 권고 — 실제 채택 경로와 토큰·테마 단일화 — 를 실행 가능한 형태로 정리했습니다. 좋은 소식: lk_web_viz는 이미 document.body에 data-theme를 세팅하고 있어 우리 DS 토큰과 추가 배선 없이 맞물립니다.

◆ 테마는 이미 호환 · 색 하드코딩만 토큰으로 이관

로드 순서 · Tailwind 공존

  2. DS 컴포넌트는 전부 var(--token) 인라인 스타일 → Tailwind 유틸리티와 충돌 없음. 클래스 이름 겹침도 없음.

  ink: 'var(--bw-ink)', signal: 'var(--lk-accent-ink)',
  surface: 'var(--surface-raised)', line: 'var(--border-subtle)',
}

02 테마 단일화

앱의 ThemeContext ↔ DS 시맨틱 토큰

앱은 이미 document.body.setAttribute('data-theme', mode) + localStorage('lk-web-viz-theme')를 씁니다. DS 토큰은 [data-theme="dark"]에서 자동 전환되므로 — ThemeContext는 그대로 두고 styles.css만 링크하면 라이트/다크가 즉시 붙습니다.

  • 중복 제거: 앱의 theme/design-tokens.ts(darkTokens/lightTokens JS 객체)는 DS 토큰과 평행한 두 번째 테마 시스템입니다. tokens.bg 같은 JS 참조를 CSS 변수로 대체하면 단일 소스가 됩니다.
  • DesignTokens 필드 → DS 변수(앱 필드명에 맞춰): bg→var(--surface-page) · surface→var(--surface-raised) · text→var(--text-body) · textMuted→var(--text-muted) · border→var(--border-subtle) · primary→var(--color-primary) · accent→var(--lk-accent-ink) · scrim→var(--scrim-dark).
  • 토글 UI: 자체 토글 대신 DS ThemeToggle(Light/Dark/Auto, data-theme + localStorage 구동)로 교체 가능 — 단, storageKey를 lk-web-viz-theme로 맞추면 기존 저장값 호환.

핵심 판단
  • 상태색은 DS가 의도적으로 muted입니다(계기판 톤). 앱의 쨍한 Tailwind 원색이 필요하면 상태가 아니라 --accent-background-*(vivid 스텝)를 쓰세요 — 단 "의미"는 항상 status 토큰으로.
  • 존/랜드마크 채움은 rgba(...,0.3) 오버레이라, DS 강조색 위에 color-mix(in srgb, var(--accent-background-blue) 30%, transparent) 또는 토큰의 -tint 변형으로 재현.
  • selected=보라(#8b5cf6)는 DS 선택 규칙(시그널틸)과 어긋납니다 — 시그널로 통일하면 존 에디터·맵 선택이 브랜드와 일치.

04 마이그레이션 순서

즉시 ROI 큰 것부터 — 화면 단위로

  1. 1주폼 · 피드백 — Login/Setup의 입력을 Input·Select·Checkbox·Radio·FormField·Button으로, react-hot-toast를 Toast·ToastStack(또는 유지+토큰만) + Banner로.
  2. 2주오버레이 · 상태 — 각종 커스텀 Dialog를 Modal·Drawer·Sheet·Alert로, 로봇/연결 라벨을 StatusBadge·ConnectionBadge로.
  3. 3주데이터 · 내비 — TaskHistory/Logs를 Table·DataGrid·Pagination으로, 상단/탭을 TopBar·Tabs·Breadcrumb로.
  4. 이후도메인 — 뷰어를 Map2DCanvas·Scene3DFrame·ViewerToolbar 셸로 감싸고, 에디터를 CanvasEditorShell·EditorToolbar·HistoryToolbar로, 로봇 선택 카드를 RobotStatusCard로, 텔레옵을 Joystick으로. 무거운 렌더(three/konva/rerun)는 그대로 유지.

각 단계 공통: 인라인 색/스타일 제거 → DS 컴포넌트 → 남은 색은 colors.ts 매핑표대로 토큰화.

05 남은 결정 사항

  • 배포 방식 — 소스 임포트 / 사내 npm 중 택1(앱 수·팀 규모 기준).
  • 도메인 경계 — 셸(DS) vs 렌더(앱) 선을 유지할지, DS가 더 owning할지. RobotStatusCard ↔ 앱 RobotCard 중복 정리.
  • 상태색 톤 — DS의 muted 상태색을 그대로 쓸지, 앱 현장 가독성을 위해 일부 vivid 유지할지.
  • 아이콘 — 혼합(fill+stroke) 세트를 Lucide 스트로크로 통일할지 + Icon.jsx 청크 분리.
